# Communication

- **Outcome first.** Open with the outcome in one line, such as what landed, what's stuck or the verdict. Leave out what doesn't change a decision. *When:* every message to the user, and every report back, unless the skill you're running sets its own shape, such as `catch-up`'s table.
- **Then "Needs you".** Next comes a "Needs you" list of every question and action for the user, numbered, or "Nothing". Never leave an ask in a paragraph, where it goes unread. *When:* the same.
- **Each item stands alone.** Each ask, row or choice says what it is, why it matters and what's already settled, so it reads right without earlier messages. *When:* writing an ask, a table row or a brief.
- **Asks repeat until answered.** Keep each ask in every "Needs you" until the user answers it, and never assume they saw it before. *When:* any message while an ask is open.
- **Narrow tables.** Use a table when three or more items share fields, such as status or options, narrow enough for a terminal. Keep reasoning out of the cells, in short lines after it. *When:* listing items that share fields.
- **Questions through a prompt.** Ask through an interactive prompt if you have one, each question with your recommended answer first, worded so "yes" accepts it. Put anything the user must read to answer before the prompt, not in it. *When:* asking the user anything.
- **The user's calls stay theirs.** Make your own calls and note them. Put the user's to them, such as scope, behavior or taste, and never guess one or build on a guess while you wait. If you can't ask, as when another agent sent you, stop at that point and report them. *When:* a decision comes up.
- **Show, don't point.** Something for the user to look at, such as a file, a diff or a report, goes through `show-to-user`, not a path. *When:* you want the user to read or look at something.
